Quick setup

  1. Select a funded wallet on the same network shown in the dashboard header.
  2. Create trustlines for every issued asset in the pair. Native XLM does not need a trustline.
  3. Create a bot and choose Buy/sell market making or Sell issued asset.
  4. Keep the first amount small and use Run once to inspect the generated order intents.
  5. Use Run dry to watch heartbeat, cycles, pricing, balances, and reconciliation without submitting offers.
  6. When the dry-run output looks correct, use Run live and confirm that real SDEX offers may be submitted.
  7. Monitor heartbeat, open offers, executions, fills, and the last-error panel.

Important: “active” is the strategy’s desired lifecycle state. A bot only places or refreshes offers while a dry-run or live worker is running.

Parameters

Price feedThe reference source. Examples: sdex:XLM/USDC/mid, sdex:XLM/USDC/bid, sdex:XLM/USDC/ask, sdex:XLM/USDC/last, or fixed:1.25.
Amount per levelBase-asset amount for each offer level. A buy-side offer also requires enough quote balance to fund it.
LevelsA sell bot creates one offer per level. A buysell bot creates one bid and one ask per level, so it creates levels × 2 offers.
Spread / offsetFor buysell, this is the total spread around the midpoint. For sell, this is the starting percentage above the reference price.
Level spacingAdditional percentage distance between successive levels.
Interval secondsMinimum time between reconciliation cycles. Shorter intervals update faster but may submit more transactions.
Maker onlyUses passive sell offers where supported, reducing the chance of immediately crossing the order book.
Max positionMaximum desired base-asset position considered by the risk checks.
Max open offersMust be at least the number of desired offers: levels for sell, levels × 2 for buysell.

Safety checklist

  • Verify the network chip before using live mode. Testnet and mainnet strategies are not interchangeable.
  • Confirm issued assets use the intended issuer address; asset codes alone are not unique.
  • Check XLM reserve and spendable balances before increasing size or levels.
  • Set Max open offers high enough for all desired offers or the cycle will fail its risk check.
  • Stopping a bot stops future reconciliation, but does not automatically cancel offers that are already open.
  • Use Cancel offers to submit an SDEX cancellation transaction for managed offers.
  • The kill switch blocks future reconciliations. Clear it deliberately after reviewing balances and parameters.
  • Dashboard runners stop when this dashboard process exits. For an independent foreground worker, run mozartpay trade run --live <strategy-id>.

Frequently asked questions

Why does an active bot say “Heartbeat: not running”?

Activate only changes the stored strategy status. Start a worker with Run dry, Run live, or the CLI trade run command.

Why are there zero offers after a run?

Check the last-error panel. Common causes are missing trustlines, insufficient balances, an invalid price feed, or fewer allowed open offers than the strategy wants to create.

What is the difference between Run once and Run dry?

Run once performs a single reconciliation and exits. Run dry repeats on the strategy interval until it is paused, stopped, or the dashboard exits.

Does Stop cancel open offers?

No. Stop prevents future reconciliation. Use Cancel offers to remove live orders from the SDEX.

What happens when the dashboard closes?

Dashboard-managed workers stop, while persisted strategy configuration and existing SDEX offers remain. Existing offers stay open until filled or canceled.

How are fills detected?

The worker reads account trades from Horizon and matches them to managed offer IDs. Fills are persisted and used for executions and performance history.

How do I specify an issued asset?

Use CODE:ISSUER, for example USDC:GBBD47IF6LWK7P7MDEVSCWR7DPUWV3NY3DTQEVFL4NAT4AQH3ZLLFLA5.

Glossary

Base asset
The asset being bought or sold, shown on the left side of a pair.
Quote asset
The asset used to price the base asset, shown on the right side of a pair.
Bid
An offer to buy the base asset using the quote asset.
Ask
An offer to sell the base asset for the quote asset.
Spread
The distance between bid and ask prices.
Midpoint
The midpoint between the best bid and best ask.
Offer
A resting order on the Stellar decentralized exchange.
Passive offer
A sell offer that will not immediately cross an existing bid.
Reconciliation
The process of comparing desired offers with live offers, then creating, updating, canceling, or leaving orders unchanged.
Trustline
An account authorization required to hold a non-native Stellar asset.
Reserve
Locked XLM required by the network for account entries such as trustlines and offers.
Fill
An executed portion of an offer recorded as a trade.
Orphaned offer
A live pair offer not tracked as managed by the current strategy.
Kill switch
A persistent safety flag that prevents future reconciliations until cleared.
P&L
Profit and loss calculated from persisted strategy activity.
